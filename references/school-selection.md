# 择校研究

用户要选学校、对比院校、问"XX 大学 XX 专业好考吗"、需要招生信息研究时使用本文档。产出是一份**有数据依据、有风险说明、可动态重评**的报告，而不是一句"这学校不错"。

## 1. 研究流程

1. 先确认用户画像：本科背景、各科基础、目标专业/城市、可接受调整范围、最看重的因素（未建画像先回 `intake-profile.md`）。
2. 生成 3-6 所候选院校，覆盖冲刺/匹配/保底三档。
3. 逐校收集官方数据（核验规则见 `info-integrity.md`）：专业目录 → 招生简章 → 参考书 → 真题与命题风格 → 历年录取数据 → 复试与学费 → 报考限制。
4. 按第 6 节结构输出报告。

## 2. 每所院校必须查清的维度

### 报考资格（发现硬性限制必须优先提醒）
学历要求、专业要求、跨考限制、工作经验、同等学力要求、前置课程、专项计划、四六级/英语要求。

### 初试难度
初试科目（英一/英二、数一/二/三）、专业课数量、统考还是自命题、专业课难度与参考书数量、真题难度与题型、命题风格。

### 历年竞争情况
招生人数、推免人数、统考录取人数、进入复试人数、复试线、最低/平均/最高录取分、初复试占比、调剂情况。

严格区分：**计划招生人数 ≠ 实际招生人数 ≠ 推免人数 ≠ 统考录取人数**。评估竞争要按推免后实际统考名额；只看"计划招生 50 人"会严重误判。

### 学校与专业实力
学科实力、师资、科研平台、就业情况、行业认可度、地域优势。不要只看综合排名，核心问题是："这个学校的这个专业，对这个用户未来的发展价值如何？"

## 3. "人"的匹配

择校不是找绝对最强的学校，而是找用户条件与学校要求的匹配点。必须综合：本科背景、专业基础、数学/英语水平、可投入时间、自律程度、学习速度、跨考代价、地域需求、就业目标、风险承受能力。

## 4. 三档候选池

- **冲刺**：历史录取数据高于用户当前水平，但通过努力有现实可能。
- **匹配**：用户基础、学习能力与历史录取情况较为匹配。
- **保底**：用户认真完成计划后，成功容错空间相对更大。

注意："保底" ≠ "肯定能上"。每一档判断必须说明：依据什么数据、数据是哪一年的、数据有什么局限、哪些因素可能导致变化。

## 5. 动态择校机制

择校是持续决策，不是一次性决策。出现以下信号时主动建议重新评估：

- 真题/模考成绩显著变化（数学、英语、专业课）
- 招生简章、专业目录、参考书发布或变化
- 距考试剩余时间发生结构性变化

给院校建议时必须附带风险说明：

- **优势**：为什么与用户匹配
- **风险**：最大的风险是什么
- **不确定性**：哪些信息目前无法确定
- **需继续观察**：最新招生计划/专业目录/参考书/复试线/推免人数
- **重新评估时间**：如"9 月底简章发布后""第一次全真模拟后"

**🔴 CHECKPOINT（更换目标院校）**：建议放弃或更换当前目标院校前，必须先向用户出示新旧院校的对比数据（含数据年份与局限）和风险说明，得到用户明确确认后才更新档案【当前择校结论】；不得擅自替用户改目标。

## 6. 择校研究报告结构

```markdown
# 择校研究报告（日期）

## 一、用户情况（引用档案）
## 二、目标专业分析
## 三、候选院校（逐校）
### 院校A
- 专业代码 / 初试科目
- 招生人数（统考，注明年份）/ 推免情况
- 历年复试线 / 录取数据
- 专业课与参考书 / 复试与学费 / 报考限制
- 数据证据表（信息|数据|来源|年份|可信度|备注）
### 院校B …
## 四、用户匹配度分析（三档归类）
## 五、主要风险
## 六、信息可信度说明
## 七、当前建议
## 八、需要继续观察的信息
## 九、下一次重新评估时间（触发条件）
```

查不到的字段明确写"未获取到官方数据"，不要编造填充。
